1Overview

The NotifyBot Inventory Summary is a web dashboard over NotifyBot's inventory file. It shows how many clusters, namespaces, app IDs and unique notification email addresses the inventory covers, how those numbers change from one inventory refresh to the next, and lets users filter the inventory and copy the matching email lists.

Inventory generator
your existing process
→
rotate_inventory.py
validate, archive, install
→
inventory.csv + archives
with .meta.json sidecars
→
Streamlit dashboard
browser, port 8501

Each time the inventory is refreshed, the previous inventory.csv is kept as an archive named inventory.csv-<epoch>. The dashboard reads these archives to draw the trend and lets users open any of them for review.

3Prerequisites & sizing

  • Linux host with Python 3.10 or newer.
  • Network access from users' browsers to the dashboard port (default 8501).
  • pip access to install streamlit (1.50 or newer) and pandas.

Sizing for ~70,000-row / ~300 MB inventory files

ItemMeasured / recommendedNotes
RAM per open file≈ 1.5 GBUp to 3 files are kept open (latest + 2 being reviewed) → plan for ≈ 5 GB free.
First open of a file≈ 7–8 sOnce per file version, shared by all users.
Clicks, tab switches, email search≈ 0.1 sResults are cached.
Changing a filter≈ 1–2 sFirst time for each filter combination.
Disk per archive≈ 300 MBWeekly refresh, 1 year ≈ 15 GB. See retention.

Low on memory? Reduce max_entries=3 to 2 on load_file in inventory_portal_st.py.

  2. Create the virtual environment and install dependencies

  3. Check the Streamlit config — /notifybot/.streamlit/config.toml should contain:

  4. Install the first inventory file (see section 7)

5Running the dashboard

Option A — manual (testing)

cd /notifybot
venv/bin/streamlit run inventory_portal_st.py --server.port 8501 --server.address 0.0.0.0 --server.headless true

Open http://<server>:8501. Stop with Ctrl+C.

Option B — systemd service (recommended)

  1. Create the unit file
    /etc/systemd/system/notifybot-inventory.service
    [Unit]
Description=NotifyBot Inventory Summary (Streamlit)
After=network.target

[Service]
WorkingDirectory=/notifybot
ExecStart=/notifybot/venv/bin/streamlit run inventory_portal_st.py --server.port 8501 --server.address 0.0.0.0 --server.headless true
Restart=on-failure
RestartSec=5
User=root

[Install]
WantedBy=multi-user.target

    Prefer a dedicated non-root user that owns /notifybot if your policies require it.

  2. Enable and start 
    systemctl daemon-reload
systemctl enable --now notifybot-inventory
systemctl status notifybot-inventory
  3. Day-to-day commands 
    systemctl restart notifybot-inventory      # after updating the .py files
systemctl stop notifybot-inventory
journalctl -u notifybot-inventory -f       # live logs
FirewallIf users cannot reach the page, open the port, e.g. firewall-cmd --add-port=8501/tcp --permanent && firewall-cmd --reload.

6Inventory file format

ColumnRequiredRules
First column (e.g. time)YesEpoch time in seconds or milliseconds. The latest value is used as the file's snapshot time and as the archive name.
emailYesAddresses separated by ; (commas also accepted). Case-insensitive; duplicates are de-duplicated.
cluster, namespace, env, appidRecommendedDrive the KPI cards and the By environment table. Missing columns show “n/a”.
Any other columnsOptionalAvailable as filter fields and in the Breakdown / Field overview tabs.

Column names are matched case-insensitively. The file must be UTF-8 CSV with a header row; a cluster + namespace pair is expected to be one row.

7Refreshing the inventory (manual)

Generate the new inventory with your existing process to any path and name, then install it with the rotate script. Never copy over inventory.csv by hand.

  1. Preview — checks the file and shows what will change, without touching anything. 
    cd /notifybot
venv/bin/python rotate_inventory.py /path/to/new_inventory.csv --dry-run
  2. Install 
    venv/bin/python rotate_inventory.py /path/to/new_inventory.csv

    Expected output:

    checking /path/to/new_inventory.csv
new file OK: 70,412 rows, latest time 1791285461 (2026-10-06 11:17 UTC)
current file will be archived as inventory.csv-1790680661
changes: Clusters 6→6, Cluster + namespace 70,100→70,412, Namespaces ..., App IDs 98→101, Unique emails ...
installed inventory.csv (70,412 rows)
done
  3. Verify — reload the dashboard. The new file appears as Latest, the previous one as the first Archived entry, and the KPI arrows show the change. No restart is needed.

What the script does

  1. Parses the new file and checks it has rows, an email column and valid epoch times.
  2. Refuses if the new file is not newer than the current one (protects against installing the same or an old export twice).
  3. Renames inventory.csv → inventory.csv-<epoch> and moves its .meta.json with it.
  4. Copies the new file in as inventory.csv with an atomic rename (users never see a half-written file). The source file is left untouched.
  5. Builds inventory.csv.meta.json, then applies --keep retention if given.

Options

OptionDefaultMeaning
--base PATHinventory.csvCurrent inventory file (use the full path when running from another folder or cron).
--keep N0 (keep all)After installing, delete all but the newest N archives.
--dry-runoffValidate and report only.
--forceoffInstall even if the new file is not newer (e.g. a deliberate correction).

8Automating the refresh

If the generator writes to a fixed location, schedule the rotate script right after it. Example — every day at 06:30:

crontab -e
30 6 * * *  cd /notifybot && venv/bin/python rotate_inventory.py /data/export/inventory_new.csv --keep 52 >> /notifybot/rotate.log 2>&1
  • If no newer export exists that day, the run logs “not newer” and changes nothing.
  • A lock prevents two rotations running at the same time.
  • Check /notifybot/rotate.log after the first scheduled runs.

10Reviewing an old inventory

  1. In the sidebar, open Inventory snapshot. Entries are listed newest first, e.g. Archived · 2026-09-16 13:59 UTC · 69,880 rows.
  2. Select the snapshot. The header turns orange with an ARCHIVED SNAPSHOT badge.
  3. All KPIs, filters, tabs and email lists now use that file. KPI arrows compare it with the snapshot before it.
  4. Switch back by selecting the Latest entry.

The first open of an archive takes ~7–8 s for a 300 MB file; after that it stays in memory (up to 3 files). Files not on the server can be loaded via Upload a file instead (limit 1 GB), but loading from the server is much faster.

Why is an archive missing from the list?An archive is hidden when its name does not match inventory.csv-<9–13 digit epoch>, or when its epoch falls inside the current file's own time range (it is then treated as a copy of the current data).

11Comparing two inventories

Use this when the trend shows a sudden jump or drop and you need to know exactly what was added or removed.

  1. At the top of the sidebar, switch View to 🔍 Compare. The header turns purple.
  2. Pick Older inventory (A) and Newer inventory (B). By default A is the previous snapshot and B the latest.
  3. Optional: add sidebar filters (e.g. env = prod) to compare only matching rows in both files.
  4. Read the results (below). Switch View back to 📊 Dashboard when done.

How rows are matched

A row is identified by cluster + namespace. (If either file lacks those columns, rows are matched on all the columns both files share.) The time column is ignored because it changes on every run.

ResultMeaning
Rows addedcluster + namespace present in B but not in A.
Rows removedcluster + namespace present in A but not in B.
Rows changedIn both files, but a field value (e.g. env: uat → prod) or the email list differs.
Emails added / removedAddresses that appear in one file and nowhere in the other (not just moved between rows).

Sections on the page

  • What changed — the five counts above, rows in A → B and the net change.
  • KPI comparison — each KPI for A and B with ▲/▼ difference.
  • Where the changes are — added / removed / changed counts per value of a field you choose (default env) and per cluster. Start here to find which environment or cluster caused a big swing.
  • Tabs — full lists of added, removed and changed rows (searchable, first 2,000 shown, CSV download for all), a summary of which fields changed, the per-row email changes with copy buttons, and the added / removed email addresses with copy and download.
PerformanceThe first comparison of a pair loads both files (~7–8 s each for 300 MB files, skipped if already open) and takes ~3 s to compare. After that, switching tabs and searching are instant. Comparing keeps both files in memory (2 of the 3 file slots).
Reading directionIf A is newer than B, a warning appears: “added” and “removed” are then reversed in time. Swap the two files to read changes forward.

12Metadata files (.meta.json)

Each CSV gets a small sidecar with its row count, snapshot time and KPIs. The trend and the snapshot list use only these, so the 300 MB archives are never read unless someone opens them.

  • A sidecar is valid while its CSV's size and modification time match what it recorded. Otherwise it is rebuilt automatically.
  • They are safe to delete at any time; they will be rebuilt (each rebuild reads the full CSV once, ~3–7 s per 300 MB file).
  • To pre-build or repair all of them:
cd /notifybot
venv/bin/python inventory_meta.py inventory.csv

Output lists each file with ok and its KPIs, or skip with the reason for unreadable files.

13Retention & disk space

  • Each archive is roughly the size of the inventory (~300 MB).
  • Use --keep N on the rotate script to keep only the newest N archives; the matching .meta.json files are removed too.
  • Removing archives removes those points from the trend chart.
check usage
du -ch /notifybot/inventory.csv-* | tail -1
ls -1 /notifybot/inventory.csv-* | grep -v meta.json | wc -l

To delete a specific archive manually, remove both files:

rm /notifybot/inventory.csv-1786546799 /notifybot/inventory.csv-1786546799.meta.json

14Rollback (bad inventory installed)

Restores the previous inventory as current. Replace <epoch> with the newest archive (the file the bad one replaced).

cd /notifybot
ls -1 inventory.csv-* | grep -v meta.json | sort -t- -k2 -n | tail -1   # newest archive = <epoch>

mkdir -p /notifybot/rejected
mv inventory.csv           rejected/inventory.csv.$(date +%Y%m%d%H%M%S)
rm -f inventory.csv.meta.json
mv inventory.csv-<epoch>           inventory.csv
mv inventory.csv-<epoch>.meta.json inventory.csv.meta.json

Reload the dashboard; no restart is needed. Fix the export, then install it again with the rotate script.

15Updating the application

  1. Back up the current code: cp /notifybot/*.py /notifybot/backup_$(date +%Y%m%d)/ (create the folder first).
  2. Copy all updated .py files from the same release into /notifybot.
  3. Restart the service — imported modules are only reloaded on restart: 
    systemctl restart notifybot-inventory
# or, if run manually:
pkill -f "streamlit run inventory_portal_st.py"; cd /notifybot && venv/bin/streamlit run inventory_portal_st.py
  4. If the release notes say the metadata format changed, nothing is required — sidecars rebuild automatically. Optionally pre-build: venv/bin/python inventory_meta.py inventory.csv.
